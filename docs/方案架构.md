# 村民意志（Village Will）方案架构文档

> 版本：v1.0（2026-08）· 状态：已确认，开发中
> 工程：`VillageWill/` · Forge 1.20.1-47.4.23 · 前置：**Guard Villagers 1.20.1-1.6.19**（最新 1.20.1 版；1.6.20 不存在，2.x/4.x 为 1.21+/NeoForge 版本）

## 1. 前置依赖侦察结论（guardvillagers 1.6.19）

来源：Modrinth 下载 `guardvillagers-1.20.1-1.6.19.jar`（`libs/`），`javap` 反编译 + GitHub `seymourimadeit/guardvillagers` 分支 `1.20.1` 源码核对。

| 项 | 结论 |
|---|---|
| modid / 配置 | `guardvillagers`；配置类 `tallestegg.guardvillagers.configuration.GuardConfig`，**运行时 API：`GuardConfig.COMMON.guardSpawnInVillage.get()`** = 每村庄自然生成的警卫数（默认 6）→ 牧师复活上限数据源 |
| 警卫实体 | `Guard extends PathfinderMob`，实现 `CrossbowAttackMob / RangedAttackMob / NeutralMob / ContainerListener / ReputationEventHandler` |
| 警卫物品栏 | **`public SimpleContainer guardInventory`**（6 槽：0=头盔、1=胸甲、2=护腿、3=靴子、4=副手、5=主手）；`getItemBySlot(EquipmentSlot)` 重定向到该容器；可公共读写 |
| 进食 AI | `GuardEatFoodGoal`（优先级0）：**只吃副手（槽4）食物**，条件 `health<max && (无目标或进食中)`；`GuardRunToEatGoal`：战斗低血（<50%）先跑开再吃；`eat(Level,ItemStack)` 按营养回血 |
| 盾牌 | `RaiseShieldGoal`（优先级0）副手持盾格挡；`shieldCoolDown` 公共字段；`disableShield(boolean)`；`isBlocking()` |
| 武器 | 主手弩→`RangedCrossbowAttackPassiveGoal`（半径配置 `guardCrossbowAttackRadius` 默认8）；主手弓→`RangedBowAttackGoal`；近战→`GuardMeleeGoal`（持弩/弓时不近战） |
| 弹药机制 | `Guard.getProjectile`：先扫 `guardInventory` 找箭（**含药水箭**，`ItemTags.ARROWS`）；找不到时**返回免费的普通箭**（不消耗）→ 天然满足"普通箭不消耗、药水箭消耗"；弩装填走 `CrossbowItem.tryLoadProjectiles → shooter.getProjectile`，同一逻辑 |
| 生成 API | `GuardEntityType.GUARD.get().create(level)` 可公共调用；`finalizeSpawn` 触发默认装备战利品表 |
| 属性 | `Guard.createAttributes()`：血量/速度/跟随范围读 guardvillagers 配置（默认 20/0.5/20），攻击基础 1.0 |
| 村民交互 | guardvillagers 已有：牧师治疗（`maxClericHeal`）、铁匠维修（`armorersRepairGuardArmor`）、村民给装备（`HealGuardAndHero` 等 brain 任务）——本模组在其上**新增升级/补给/复活/附魔**，不改其行为 |

**结论**：全部需求均可通过公共 API + 事件实现，无需 Mixin、无需修改 guardvillagers。

## 2. 总体架构

```
com.villagewill
├── VillageWill.java            # 主类：现有 BLOCKS/ITEMS + 挂载新增 DeferredRegister
├── config/
│   └── Config.java             # 重写：ForgeConfigSpec（SERVER 类型），全部功能开关/数值
├── registry/
│   ├── ModEntities.java        # stone_golem / thrown_stone / guard_captain
│   ├── ModBlockEntities.java   # village_core BE
│   └── ModMenuTypes.java       # village_core menu
├── compat/
│   └── GuardCompat.java        # guardvillagers 适配层：GuardEntityType/GuardConfig/Guard 全部访问集中于此
├── capability/
│   ├── CapabilityRegistry.java # 能力注册与 attach（EntityJoinLevel）
│   ├── VillagerJobMemory.java  # 村民：今日已用次数/最后处理日/牧羊犬UUID/职业快照
│   └── GuardBuffState.java     # 警卫：各槽升级层/武器层/被顶替盾牌/存粮标记
├── village/
│   ├── VillageContext.java     # 村庄定义：以核心/钟为中心半径64（config）；范围内实体查询
│   ├── VillageState.java       # SavedData：绿宝石/科技等级/墙壁位置/小屋数/队长UUID/每日结算
│   ├── DailyCycle.java         # 服务端每日循环：换天重置、结算、日出复活
│   └── ThreatScanner.java      # 300格威胁扫描（仅已加载区块）+ 队长任务分发
├── behavior/                   # 阶段一：村民行为模块（每个职业一个类）
│   ├── GuardFoodLogic.java     # 功能1+8：副手面包/牛排优先级/盾牌归还
│   ├── ArmorerAction.java      # 功能2
│   ├── FarmerAction.java       # 功能3
│   ├── ClericAction.java       # 功能4
│   ├── WeaponsmithAction.java  # 功能5
│   ├── LibrarianAction.java    # 功能6
│   ├── FletcherAction.java     # 功能7
│   ├── ButcherAction.java      # 功能8
│   ├── EnhanceGoal.java        # 功能9：村民走向警卫→执行→特效
│   └── ActionEffects.java      # 功能9/10：粒子/音效（服务端广播）+ 村民经验
├── building/                   # 阶段二
│   ├── MasonBuilder.java       # 小屋建造/选址（趋向正方形）
│   └── ShepherdLogic.java      # 床/牧羊犬
├── entity/                     # 阶段二/三
│   ├── StoneGolem.java / ThrownStone.java
│   └── GuardCaptain.java（+AI 子包）
├── block/
│   ├── VillageCoreBlock.java / VillageCoreBlockEntity.java
│   └── VillageCoreMenu.java / VillageCoreScreen.java（@OnlyIn(Dist.CLIENT)）
└── util/
    ├── TierUpgrade.java        # 装备/武器层级路径（可配置）
    ├── EnchantRoll.java        # 附魔台规则随机附魔封装
    └── EffectApplier.java      # 效果/粒子/音效工具
```

**遵守的约束**：
1. 新方块/物品沿用主类现有 `BLOCKS`/`ITEMS` DeferredRegister；实体/BE/Menu 各建一个标准 DeferredRegister，无自定义注册框架
2. 不修改已有 ID、包名、Mod ID；不改 guardvillagers
3. 游戏逻辑全部服务端；仅 Screen/渲染器标注 `@OnlyIn(Dist.CLIENT)`；粒子/音效用 `ServerLevel.sendParticles`/`Level.playSound` 服务端广播，无需自定义数据包
4. 玩家声望聚合原版 gossip（`Villager.getPlayerReputation`），不新建玩家存储
5. 伤害/冷却/状态一律以服务端为准

## 3. 数据与状态设计

### 3.1 Capability（实体 NBT 持久化，`AttachCapabilitiesEvent<Entity>`）

| 能力 | 挂载对象 | 字段 |
|---|---|---|
| `VillagerJobMemory` | Villager | `lastDayProcessed`(long)、`actionUsesToday`(Map<String,Integer>)、`lastProfession`(String 职业快照)、`dogUUIDs`(List<UUID>) |
| `GuardBuffState` | Guard | `armorTiers`(int[4] 每槽升级层)、`weaponTier`(int)、`displacedShield`(ItemStack NBT)、`lastMealTime`、`storedSteak`/`storedBread` 缓存 |

### 3.2 VillageState（SavedData，按村庄核心坐标命名存档）

| 字段 | 用途 |
|---|---|
| `emeraldBalance`(long) | 村庄核心绿宝石余额 |
| `techBeacon`（效果/等级/范围） | 信标科技 |
| `techWall`（等级、已放置方块位置列表） | 围墙 |
| `techCaptain`（血量/攻击/附魔等级）、`techEscort`（装备/附魔）、`techGuard`（血量/攻击） | 强化科技 |
| `houseCount`、`wallPositions` | 石匠/围墙 |
| `captainUUID`、`captainEquipment`(NBT) | 队长与复活数据 |
| `lastDailyDay` | 每日结算防重 |

### 3.3 配置（`Config.java` 重写，SERVER 类型）

全部功能开关 + 数值默认值（下表 §5）。节：`general` / `guards` / `jobs.armorer|farmer|cleric|weaponsmith|librarian|fletcher|butcher` / `mason` / `shepherd` / `villageCore` / `captain`。

## 4. 三阶段功能设计

### 阶段一：警卫食物与六大职业互动（功能 1–10）

| # | 功能 | 实现要点（全部服务端） |
|---|---|---|
| 1 | 警卫面包回血+盾牌归还 | `GuardFoodLogic`：无目标且受伤时，扫 `guardInventory`（槽0–3）找面包 → 记录被顶替的副手盾牌到 `GuardBuffState.displacedShield` → 面包放入槽4 → `GuardEatFoodGoal` 自动吃；槽4 空且记录有盾牌 → 归还盾牌。战斗时不执行 |
| 2 | 盔甲匠升级/维修 | `ArmorerAction`：目标警卫在村庄内；空槽先发基础甲（层级=盔甲匠等级映射材质）；已有甲升级（皮革→锁链→铁→钻石→下界合金，层级上限=职业等级）；维修=耐久清零（消耗铁，可由交易量判定）；每日次数=等级+1（1级2次）；升级换新装备→附魔自然丢失；维修原装备→附魔保留 |
| 3 | 农民补面包 | `FarmerAction`：凭空生成面包放入空槽（优先槽4→槽3…）；优先无面包警卫；数量/次数：1级6×2、2级8×2、3级10×3、4级14×4、5级16×5（可配置） |
| 4 | 牧师日出复活 | `ClericAction`（`DailyCycle` 触发）：村庄内警卫数 < `GuardConfig.COMMON.guardSpawnInVillage.get()` 时，`GuardEntityType.GUARD.get().create` + `finalizeSpawn` 生成**全新**警卫（默认装备）；数量：1级1、3级2、5级3（2级1、4级2） |
| 5 | 武器匠升级/维修 | `WeaponsmithAction`：主手剑/斧按材质升级（石→铁→钻石→下界合金，上限=等级）；**弩跳过**；弓仅维修（无材质层级）；维修恢复耐久；1次/天 |
| 6 | 图书管理员附魔 | `LibrarianAction`：随机选警卫一件武器/盔甲，`EnchantmentHelper.enchantItem(random, stack, 附魔等级, false)`（=附魔台N级规则）；等级=10×职业等级，每日次数=(等级+1)/2；已升级的新装备无附魔→"升级不保留附魔"天然成立；维修不换装备→附魔保留 |
| 7 | 制箭师药水箭 | `FletcherAction`：仅主手**弩**的警卫；随机毒/缓/弱之一，`PotionUtils.setCustomEffects`（增幅0/1/2=I/II/III）；1级8支I×2次、3级12支II×2次、5级16支III×2次（2级8支II、4级12支III）；放入 `guardInventory` 中被 `getHeldProjectile` 先扫描的槽位实现"优先使用药水箭"；药水箭随弩消耗、普通箭免费——guardvillagers 原生行为，无需干预 |
| 8 | 屠夫牛排 | `ButcherAction`：1–5级给1–5块，2次/天；`GuardFoodLogic` 食物优先级：**战斗中→牛排，和平→面包** |
| 9 | 交互感 | `EnhanceGoal`（注入村民 goalSelector，优先级0，`EntityJoinLevelEvent`）：村民寻路至目标警卫（距离≤2.5 执行）；执行后 `ActionEffects.playTradeComplete`：服务端 `sendParticles(HAPPY_VILLAGER)` 广播 + `SoundEvents.VILLAGER_YES`；NPC 间双向：若警卫过远（>48），改为等待警卫（警卫有 MoveBackToVillageGoal 会回村） |
| 10 | 村民经验 | `ActionEffects.grantXp(villager, n)`：`Villager.setVillagerXp(getVillagerXp()+n)` 触发升级判定；每次动作默认 2 点（可配置） |

### 阶段二：石匠与牧羊人

| 功能 | 实现要点 |
|---|---|
| 石匠小屋 | 每天最多1栋、全村≤15栋；选址算法：以村庄中心为原点把地块划成正方形网格（螺旋填充，先补短边→村庄轮廓趋向正方形）；寻平/填平地（地表±1整平，草径地面）；小屋=墙+屋顶+门洞+**2个职业方块**（石匠自身工作点石切机 + 随机职业方块），无床；记录 `houseCount` 与地块到 `VillageState` |
| 石傀儡 | `StoneGolem extends SnowGolem`：复用雪傀儡模型/AI（改投掷）；`ThrownStone extends ThrowableItemProjectile`：命中伤害+缓慢（等级=石匠等级）；属性按表（1级攻2缓I 15血10甲1韧 → 5级攻7缓V 30血20甲3韧，全部可配置）；每个石匠≤2只（`VillagerJobMemory` 计数） |
| 牧羊人 | 在小屋内放床（每屋2张，`VillageState` 记录）；村民职业变为牧羊人（`VillagerCareerChangeEvent` 若存在，否则 tick 快照比对）→ 生成2只驯服狼（owner=牧羊人），血/攻随等级缩放（等级×配置倍率）；失业/转职 → 狼 `discard()` |
| 材质 | 程序生成灰色岩石风占位图：石傀儡（雪傀儡模板改灰+噪声纹路）、石头球、村庄核心，构建期脚本输出 PNG |

### 阶段三：村庄核心与警卫队长

| 功能 | 实现要点 |
|---|---|
| 核心转换 | 村民（不含警卫，`instanceof Guard` 排除）≥20 → 最近村庄中心的钟原地替换为 `VillageCoreBlock`（不可破坏：`getDestroyProgress`=0、爆炸免疫、不掉落）→ 生成队长；`VillageState` 初始化 |
| 绿宝石收入 | 每日结算：范围内村民每人1颗（3级2、5级3），无交互直接入账 |
| 强加载 | 核心区块 ForgeChunkManager ticket（BE 生命周期校验）；队长同款（跟随实体） |
| GUI | 右键打开 `VillageCoreMenu`：村民数、警卫数、玩家声望（聚合村庄内村民 gossip）、绿宝石余额、各科技等级——**只读** |
| 科技树（自主） | `DailyCycle`/每 N tick：按优先级自动购买——①信标：初始再生I 50×50（村民/警卫/傀儡/高声望玩家），可购速度/急迫/抗性/跳跃/力量 + 等级II + 范围升级；②围墙：围绕村庄建墙留通道（预留15小屋余量），材质升级（圆石→石砖→深板岩砖，替换 `wallPositions`）；③队长：血/攻/装备附魔升级、复活（装备从 `VillageState.captainEquipment` 恢复）；④护卫：装备/附魔升级、复活；⑤警卫：全村警卫血/攻升级（新生成警卫自动应用）；花费随等级递增（可配置） |
| 威胁扫描 | 每 100 tick：以核心为中心 300 格，仅已加载区块的敌对生物，按加权威胁分（可配置 `type:weight` 列表）取最高 → 派队长任务 |
| 警卫队长 | `GuardCaptain extends PathfinderMob`（独立 AI，不用警卫 AI）：80血、下界合金套、力量IV+无限弓、免疫全部负面效果（`canBeAffected` 拦截 + tick 清除）、装备不可破坏（Unbreakable 组件 + 拦截耐久损耗）；4名护卫 = `GuardEntityType.GUARD` 生成（铁套）并注入高优先级跟随队长 goal；无任务巡逻村庄（以核心为中心漫游），有任务追杀目标；目标在地下→无伤爆炸开路（`level.explode` + `ExplosionDamageCalculator` 恒0伤害 + DESTROY），高处→垫方块（虚拟方块库存），空中目标→弓射 |

## 7. 交付流程与验收

每阶段：实现 → `gradlew.bat build` 通过 → 部署 `.minecraft/mods/` → PCL 实测 → git 提交推送（`git add -A` → `commit` → `push`）。
阶段完成输出：修改文件列表 / 核心实现思路 / 关键代码位置 / 游戏内测试步骤 / 兼容性风险。

## 8. 兼容性风险（预判）

1. **guardvillagers 版本锁定**：编译期绑定 1.6.19；若后续它更新 API，需同步 `mods.toml` 范围与适配层（`GuardCompat` 已隔离全部访问点）
2. **村民 brain 与注入 Goal 的寻路竞争**：村民脑内日程（睡觉/工作）可能抢导航；对策=目标高优先级+每 tick 重算路径+只在清醒时段执行，需实测
3. **警卫 6 槽全为装备槽**：面包/箭占用 0–3 槽会影响"该槽暂无装备"时的表现（如面包在头盔槽会渲染），已在放物策略上避开（优先副手/低干扰槽）
4. **威胁扫描性能**：300 格×已加载区块的实体扫描有开销；用周期节流（默认100tick）+ 预筛选类型
5. **区块强加载**：队长/核心 ticket 需在实体卸载/死亡时正确释放，否则区块泄漏；复活后重注册
6. **核心替换钟**：村民集会点消失可能影响村民日程（可接受，需实测观察）
